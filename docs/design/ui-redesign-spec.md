# UI Redesign Spec v1 (Desktop)

- Project: 工程造价规范检索助手
- Scope: 用户端全站（首页 / 规范检索 / 检索详情 / 问规则 / 试用）
- Excluded: `/admin`、`/admin/login`
- Date: 2026-03-17
- Output Type: 本地高保真规范（后续迁移至 Figma）

## 1. 体验审计与统一页面模型

### 1.1 现状审计结论

当前前端具备完整业务链路（首页引流 -> 检索/问答 -> 试用），但存在以下设计一致性问题：

1. 信息层级偏平，关键动作（提交问题、申请试用）视觉优先级不稳定。
2. 页面密度接近“管理台样式”，缺少“专业信息化产品”的品牌区分度。
3. 各页面相同语义组件（卡片、提示、筛选、状态反馈）样式不完全一致。
4. 空态、错误态、加载态表达不统一，用户认知成本偏高。
5. 局部文案存在异常字符风险（尤其检索详情页），影响专业感与可信度。

### 1.2 统一页面模型（Desktop First）

所有用户端页面采用统一骨架：

1. `Global Header`: 品牌 + 一级导航 + 主 CTA。
2. `Page Intro`: 页面标题、任务描述、次级 CTA。
3. `Primary Workspace`: 当前任务核心交互区（检索、问答、表单）。
4. `Evidence / Result Zone`: 结果列表、引用、详情原文。
5. `Trust Layer`: 风险提示、适用边界、服务承诺。
6. `Global CTA + Footer`: 试用转化与收尾信息。

### 1.3 信息架构规则

1. 用户从首页进入“查规范 / 问规则 / 试用”均不超过 2 次点击。
2. 每页仅保留 1 个主行动按钮（Primary），其余为 Secondary/Tertiary。
3. 风险提示位于结果区域附近，不与核心输入区竞争视觉焦点。
4. 业务术语统一：规范、依据、条款、引用、试用申请。

## 2. 视觉方向（专业信息化 + 中度品牌重塑）

### 2.1 设计关键词

- 可信、清晰、克制、可追溯。
- 信息化中控气质（非深色大屏），强调数据与规则的严谨感。
- 在现有蓝色基础上升级为“深海蓝 + 青绿辅助 + 橙色提醒”。

### 2.2 桌面画板基线

1. 画板宽度：1440。
2. 主内容容器：1200（左右留白自动）。
3. 栅格：12 列，列间距 24。
4. 主区块垂直间距：48。
5. 区块内标准间距：24 / 16 / 12。

## 3. 页面高保真模板（5 套）

## 3.1 首页模板（Home）

### 页面目标

首次访问用户快速理解能力边界，并进入检索或问答。

### 区块结构

1. Hero（品牌价值 + 快速检索输入 + 双入口 CTA）。
2. 核心能力矩阵（查规范 / 查依据 / 问规则 / 试用）。
3. 典型适用场景（4 卡片）。
4. 风险与边界说明（高识别提醒条）。
5. 企业试用转化区（双按钮）。

### 关键设计决策

1. Hero 区引入“规则检索流程图”背景纹理（弱对比）。
2. 主按钮固定为“进入规范检索”，次按钮为“去问规则”。
3. 风险提示采用琥珀浅底 + 深色标题，增强法务语义。

## 3.2 规范检索页模板（Search）

### 页面目标

快速输入关键词，完成筛选、结果浏览与详情跳转。

### 区块结构

1. Page Intro（标题、说明、试用 CTA）。
2. 检索输入区（关键词输入 + 检索按钮）。
3. 筛选工具条（分类下拉、关键词回显、结果统计）。
4. 结果列表区（Result Card 列表）。
5. 空态/错误态模块（统一卡片）。

### 关键设计决策

1. 工具条固定高度，状态提示与筛选控件同轴对齐。
2. 结果卡片顶部展示“规范编号 + 分类 + 日期”证据标签。
3. 空态内置可执行建议（缩短关键词、改编号、换分类）。

## 3.3 检索详情页模板（Search Detail）

### 页面目标

查看条款上下文、页码、版本与原文，支撑复核留痕。

### 区块结构

1. 顶部返回条（返回检索页 + 当前页标题）。
2. 证据摘要卡（编号、分类、发布日期、章节、页码、版本）。
3. 原文主卡（高可读文本排版，支持长文本）。
4. 来源信息卡（source）。

### 关键设计决策

1. 章节路径采用面包屑式视觉表达，降低层级歧义。
2. 原文区行高提高到 1.9，提升长段阅读体验。
3. 引入“复制条款”次级按钮（设计预留，不改本轮代码）。

## 3.4 问规则页模板（QA）

### 页面目标

让用户在清晰边界下提问，并获得带引用的回答。

### 区块结构

1. Page Intro（标题、方法说明、试用 CTA）。
2. 风险提示条（回答边界声明）。
3. 问题输入区（文本域 + 示例问题 chips + 提交按钮）。
4. 回答卡（内容、模型信息、状态反馈）。
5. 依据引用列表（文档、章节、页码、摘录）。

### 关键设计决策

1. 回答卡与引用卡视觉分层，先答案后证据。
2. 提交按钮仅在输入满足长度时可用，禁用态高可辨。
3. 示例问题 chip 统一为“淡底描边 + hover 强化”。

## 3.5 试用页模板（Trial）

### 页面目标

收集企业线索并清晰传达服务范围。

### 区块结构

1. 页面说明卡（适用对象 + 服务说明）。
2. 试用表单（联系人、联系方式、邮箱、需求类型、需求描述）。
3. 提交反馈区（成功/失败提示）。
4. 数据使用说明（低优先级说明文案）。

### 关键设计决策

1. 表单采用两列栅格，长文本需求区独占一行。
2. 表单成功/失败反馈使用统一 Alert 组件规范。
3. 用词统一为“试用申请”，避免“留资”等内部术语直接暴露。

## 4. 交互状态覆盖规范

重点覆盖 Search / QA / Trial：

1. `default`: 输入与卡片常态。
2. `hover`: 可点击元素投影或描边增强。
3. `focus`: 输入框 2px 语义色 focus ring。
4. `loading`: 按钮 loading + 区块 skeleton/提示语。
5. `empty`: 结果为空时展示建议动作。
6. `error`: 错误提示卡，含可恢复指引。
7. `success`: 成功反馈卡，语气简洁且可继续下一步。

## 5. 文案治理执行范围

1. 统一术语：规范、条款、依据、引用、试用申请。
2. 统一语气：专业、直接、避免夸张营销表达。
3. 优先修复检索详情页异常文案与占位符表达。
4. 详见 `copy-deck-v1.md` 的页面级文案清单与替换建议。

4. 颜色必须绑定语义变量，不直接写十六进制。

## 7. 验收清单

1. 首页到“查规范/问规则/试用”路径不超过 2 次点击。
2. 5 个页面模板在视觉语言上统一且区分主次动作。
3. Search/QA/Trial 的 7 类状态均有明确高保真定义。
4. 文案无乱码、术语统一、风险边界清晰。
5. 文档可直接作为 Figma 搭建输入，无额外决策依赖。
